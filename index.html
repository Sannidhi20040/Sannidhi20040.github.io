Traffic Drone Geo-Referencing System

YOLOv8 · VisDrone · ONNX in the browser · Flight-log telemetry · Leaflet

Detects small vehicles, large vehicles and people in drone video, then turns each detection into a position on a map.

  • Detection: YOLOv8 trained on VisDrone (9,287 images), mAP50 0.583, exported to ONNX and run in the browser.
  • Telemetry sync: video frames are synchronised with flight-log telemetry.
  • Geo-referencing: each detection is converted to a GPS coordinate using altitude, field of view and drone heading.
  • De-duplication: repeat detections within 5 m are merged.
  • Output: an interactive Leaflet map, with GeoJSON and CSV export.

GPU Kernels for Vision and LLM Workloads

CUDA · Triton · PyTorch · NVIDIA Tesla T4

A from-scratch learning project in GPU programming: custom CUDA and Triton kernels for image preprocessing and LLM layers, each tested against a PyTorch reference and benchmarked against eager PyTorch and torch.compile. Every number is reported as measured, including the cases where PyTorch wins.

Highlights (Tesla T4)

  • Fused image preprocessing (Triton): uint8 HWC to normalised float CHW in one pass. 4.6× faster than eager PyTorch and 1.2× faster than torch.compile at 1080p, with output matching PyTorch exactly in fp32.
  • Fused RMSNorm (Triton): 1.15–1.28× faster than PyTorch’s F.rms_norm and 1.07–1.12× faster than torch.compile at LLM hidden sizes 4096–8192 (fp16), at about 65% of peak memory bandwidth.
  • Pairwise IoU (Triton): 12–14× faster than torchvision.ops.box_iou at N = 4096–8192.
  • Fused softmax (Triton): up to 1.5× faster than torch.softmax on long rows.
  • CUDA warm-ups: warp-shuffle reduction (~58% of peak bandwidth), naive vs tiled matmul, direct convolution.

All 64 tests pass on the GPU, and every CUDA program checks its own output.

What I learned

  • Fusion is about bytes, not math. Eager preprocessing launches 4 kernels and moves about 5.8× more data than one fused pass; that traffic accounts for almost the entire speedup.
  • Compare against the strong baseline. torch.compile also fuses, so the honest comparison is 1.2×, not 4.6×. I report both.
  • Know where a kernel loses. RMSNorm and softmax are slower than PyTorch on short rows, and shared-memory tiling made the 3×3 convolution slower because the hardware caches already captured the reuse.

Limitations: tested on one GPU model (T4); RMSNorm is forward-only; the tiled matmul reaches 17% of cuBLAS. A learning project, not a replacement for vendor libraries.
